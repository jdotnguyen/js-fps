# audio-assets Specification

## Purpose

Defines how sounds are named, where their audio comes from, and how recorded files replace procedural placeholders, so new sound can be added or swapped without touching the systems that play it.

## Requirements

### Requirement: Sounds are played by name
Game systems and sequence steps SHALL request sounds by a stable name, not by file path. The name SHALL stay the same when its audio source changes from procedural to recorded, or from one recording to another.

#### Scenario: Swap a recording
- **WHEN** a sound's recorded file is replaced with a new ElevenLabs take under the same name
- **THEN** every system that plays that name uses the new take with no code change

### Requirement: Recorded files are the default source
Every sound that has a recorded file in the registry SHALL play that file once it has loaded. Procedural audio SHALL only be a fallback.

#### Scenario: File and fallback both exist
- **WHEN** `hullGroan` has both a recorded file and a procedural fallback, and the file has loaded
- **THEN** only the recorded file is heard

### Requirement: Procedural fallback until the file loads
A sound with a procedural fallback SHALL be playable from the first frame. When its recorded file finishes loading, new plays SHALL use the file, and loops already running on the fallback SHALL switch to the file without stopping.

#### Scenario: Room tone before decode
- **WHEN** the room-tone loop starts before its recorded bed has decoded
- **THEN** the procedural room tone plays, and switches to the recorded bed once it is ready without a gap

### Requirement: Failed or missing files degrade safely
If a recorded file is missing or fails to decode, the sound SHALL keep using its procedural fallback, or stay silent if it has none, and SHALL log one warning. The game SHALL keep running.

#### Scenario: Missing door clip
- **WHEN** a door clip returns 404
- **THEN** one warning is logged, the door makes its fallback sound or none, and play continues

### Requirement: Variants
A sound name MAY map to several recorded files. Each play SHALL pick one of them so that repeated sounds are not identical.

#### Scenario: Footstep variety
- **WHEN** the player walks ten steps on concrete
- **THEN** the steps draw from the seven concrete takes rather than repeating one clip

### Requirement: Unknown names in content are reported
A sequence step that names a sound which does not exist SHALL log a warning naming the sound and SHALL be skipped, not crash the sequence.

#### Scenario: Typo in a sequence
- **WHEN** a sequence runs `{ "do": "sfx", "id": "hullGrown" }`
- **THEN** a warning names `hullGrown` and the sequence continues with its next step

### Requirement: Procedural sound is fallback-only
New sound effects and ambience SHALL be added as recorded files. Procedural audio SHALL NOT be added for new sounds, and procedural sounds that no system or content plays SHALL be removed. Existing fallbacks for sounds still in use SHALL be kept.

#### Scenario: Adding a new SFX
- **WHEN** a new valve-turn sound is needed
- **THEN** it is generated as a recorded file and registered by name, with no new procedural synth

### Requirement: One provider per asset class
Environmental ambience, door foley, footsteps and other new sound effects SHALL come from ElevenLabs SFX. Character dialogue and non-verbal vocal reactions SHALL come from Gemini TTS. Clips from other sources SHALL be allowed only where an existing class already uses them (zombie voices, UI clicks, weapons).

#### Scenario: New ambience bed
- **WHEN** a new room needs an ambience bed
- **THEN** it is generated with the ElevenLabs ambience script, not a different provider

### Requirement: Third-party audio is credited
Any recorded audio not generated by the project's own scripts SHALL be listed in `CREDITS.md` with its author, source and licence before it ships.

#### Scenario: Add a CC0 clip
- **WHEN** a CC0 grunt from OpenGameArt is added to the registry
- **THEN** `CREDITS.md` lists the clip, its author, its source link and CC0
